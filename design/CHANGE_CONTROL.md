## 13. Change control (design/CHANGE_CONTROL.md)
Any change to frozen bytes: written proposal (what/why/evidence) → diff confined to named hunks → review by class (science: the 5-lane one-review law; code: red-first fixture proving defect + fix + mechanical re-verify of exactly the failing fixtures + full suite) → version bump + evidence row + PROGRESS/STATE update. No silent edits ever; hotfixes get priority, not exemption. FINAL_PLAN.md content changes only through this procedure (progress lives in PROGRESS.md, never by editing the plan).
